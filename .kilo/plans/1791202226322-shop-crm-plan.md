# План: мини-CRM продуктового магазина (shop-crm)

## Контекст

ТЗ лежит во вложении (`f3894927-...md`), прототип `shop-crm.jsx` из раздела 1 в репозитории
отсутствует — экраны и поведение придётся восстанавливать по тексту ТЗ. Репозиторий `sap-studies`
практически пуст (только README), код проекта размещается в `shop-crm/`.

## Принятые решения (расхождения с ТЗ зафиксированы)

| Вопрос | Решение |
|---|---|
| Язык бэкенда | **Go** вместо Node/TypeScript из ТЗ (прямое указание пользователя) |
| Фронтенд | React + TypeScript + Vite + Tailwind + TanStack Query + React Router — как в ТЗ |
| Go-стек | chi + pgx + golang-migrate + go-playground/validator |
| Локализация | ru + en, i18next, переключатель в шапке, ru по умолчанию |
| Ошибки API | сервер: `code` + английский текст-фолбэк; фронт переводит по `code` |
| Списание бонусов | клиент шлёт `bonusPercent` (0–50); сервер сам ограничивает балансом |
| Тестовая БД | testcontainers-go, миграции накатываются в контейнере |
| История решений | Conventional Commits + `docs/decisions/ADR` |
| Авторизация | вне MVP, но слой ролей оставляется расширяемым |

Токен, присланный в чат (`ghp_…`), отозван пользователем; код с GitHub работает только через
`gh auth login` / переменную окружения. Токен нигде не сохранять.

## Модель данных

Без изменений относительно раздела 6 ТЗ: `products`, `customers`, `sales`, `sale_items`.
Деньги — целые числа (`integer`/`bigint`) в копейках; CHECK-ограничения `stock >= 0`,
`price_kop > 0`, `qty > 0`, `bonus_balance >= 0`. Индексы: `customers(phone)`,
`customers(card_number)`, `sales(created_at desc)`, `sale_items(sale_id)`.

Seed: 8 товаров, 3 покупателя (карты `5000-0001`…), накатывается автоматически при старте.

## Контракт бонусов (ADR 0002)

```
subtotal      = Σ price_kop_snapshot × qty
bonusSpend    = min(floor(subtotal × bonusPercent / 100), customers.bonus_balance)
total         = subtotal − bonusSpend
bonusEarned   = floor(total × 5 / 100)        // кэшбэк от фактически оплаченного
```
Без карты (`customerId` отсутствует): `bonusPercent` игнорируется, списания и начисления нулевые.
Валидация: `bonusPercent` ∈ [0, 50], `qty` ≥ 1, дублей productId в чеке нет (сливаются на сервере).
Расхождение 1 бонуса с предпросмотром на клиенте допустимо — источник истины сервер.

## Этапы работ

1. **Каркас**: `go.mod`, chi-роутер, health-эндпоинт, конфиг из env, docker-compose
   (postgres + backend + frontend), `.env.example`, многоязычный README, папка ADR.
2. **Миграции и seed**: `0001_init`, автонакат при старте, seed из миграции.
3. **lib/money + lib/errors + calculateSale** с юнит-тестами: без карты, нехватка бонусов,
   округления вниз, нулевой процент, пустой чек.
4. **Модуль products**: CRUD, restock, мягкое удаление через `archived`, тесты.
5. **Модуль customers**: выдача карты последовательно (`5000-0001`), поиск с серверной
   фильтрацией, 409 на дубль телефона (unique + перехват нарушения).
6. **Модуль sales**: POST в одной транзакции — `SELECT … FOR UPDATE` по товарам и покупателю,
   проверка остатков, вставка чека и позиций, уменьшение остатков, обновление бонусов;
   падение на любом шаге откатывает всё. Пагинация по 20, состав чека в ответе.
7. **Фронтенд-оболочка**: Vite, Tailwind в фирменных красном/зелёном, i18n-провайдер,
   переключатель языка, роутер, api-клиент с маппингом кодов ошибок.
8. **Страницы**: Products, Customers, Sales + пустые состояния и ссылки на кассу.
9. **Касса**: плитки товаров, чек с плюс/минус, выбор карты, слайдер/инпут процента бонусов,
   предпросмотр расчёта, «Пробить чек» с понятными ошибками без очистки чека.
10. **Полировка**: адаптивность от 360 px, фокус, подписи у иконок, ESLint/Prettier, README.

## Проверка

- `go test ./...` — юнит-тесты `calculateSale` и денежных конвертаций.
- `go test ./tests/...` — интеграционные на testcontainers: невалидное тело 400, пустой чек 400,
  неизвестный товар/покупатель 404, нехватка остатка 409 без изменения остатков и бонусов,
  гонка двух параллельных `POST /sales` за последнюю единицу (один 201, второй 409),
  смена цены не меняет прошлый чек.
- `docker compose up` поднимает всё с нуля, миграции и seed применяются сами.
- Критерий 2 вручную: сумма 1000 ₽, баланс 800, `bonusPercent: 50` → списано 500,
  оплачено 500 ₽, начислено 25.
- Переключение языка на каждой странице, включая тексты ошибок 409.

## Риски

- `shop-crm.jsx` отсутствует: оформление придётся восстанавливать по описанию. Не блокер,
  но визуал кассы придётся уточнять в процессе.
- Автоматический seed в любом окружении: при повторном старте контейнера данные не
  дублируются (идемпотентный `ON CONFLICT DO NOTHING`).
- Переводы, зашитые в `ru.json`/`en.json`, разъедутся с текстами сервера; ключи держать в
  одном файле-эталоне и проверять отсутствие сырых ключей в UI.
