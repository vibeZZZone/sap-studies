# 0003. Локализация ru/en и перевод ошибок на клиенте

**Статус:** принято
**Дата:** 2026-10-05

## Контекст

ТЗ требует «весь интерфейс на русском» и понятные тексты ошибок. Пользователь отдельно
попросил русскую и английскую локализацию и двуязычную документацию.

## Решение

- Интерфейс полностью локализован: `src/i18n/locales/ru.json` и `en.json`, переключатель
  в шапке, язык сохраняется в `localStorage`, по умолчанию `ru`.
- Сервер отдаёт ошибку в виде `{ "error": { "code", "message", "params" } }`.
  `code` — стабильный идентификатор (`INSUFFICIENT_STOCK`), `message` — английский текст
  для fallback.
- Клиент переводит по `code`; если код неизвестен, показывает `message` сервера.
- `params` несут контекст: например, `productId` в 409, чтобы сообщение назвало товар.

## Почему не Accept-Language на сервере

Вариант с `Accept-Language` означал бы держать локализацию в двух местах и гонять
серверные тесты для обоих языков. При текущей схеме переводы живут в одном файле на
клиенте, а сервер остаётся языконезависимым — что важно для учебного проекта и для
будущего CLI или мобильного клиента.

## Последствия

- Каждый новый код ошибки обязан появиться в обоих бандлах; отсутствующий ключ
  откатывается на английский текст сервера, а не ломает экран.
- README и ADR двуязычные.
